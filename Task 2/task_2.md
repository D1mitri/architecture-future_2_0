1. В DWH на данный момент находится много информации. Финансовые данные предлагется перенести в финтех систему, т.к. это соответствует её направлению.
2. Новые интеграции (фармацевтика и электроника) выделены в отдельные домены, чтобы ими было проще управлять и развивать независимо от основной системы.
3. ИИ-система работает с конфиденциальной информацией, поэтому её важно вынести отдельно и реализовать необходимый уровень защиты данных, используя RBAC, шифрование данных в покое на уровне БД и при передаче в системе (TLS, HTTPS)
4. DWH в перспективе будет либо сильно уменьшена по объему данных и бизнес-логике, либо вовсе заменена новыми системами. Например витрина данных часть информации заберет из DWH для улучшения скорости формирования отчетов.

# Привязка бизнес-сценариев к потокам:

### Сценарий 1: Оформление кредита на лечение

1. Пациент выбирает лечение -> Мед.домен отправляет факт (услуга, стоимость)
2. Фин.домен создает кредитное предложение -> одобрение
3. Фин.домен подтверждает оплату -> Мед.домен начинает лечение

### Сценарий 2: Анализ эффективности клиник

1. Ежедневно: Мед.домен -> Data Lake (агрегированные данные по пациентам)
2. Ежедневно: Фин.домен -> Data Lake (доходы/затраты)
3. Аналитик в аналитическом домене строит отчет "Рентабельность по филиалам"

### Сценарий 3: ИИ-диагностика по снимкам

1. Врач загружает анонимные снимки -> ИИ-домен
2. ИИ-сервис анализирует -> возвращает диагноз с вероятностью
3. Результат сохраняется в мед.карту (с согласия пациента)
4. Анонимные данные -> дообучение моделей

# Методика разбиения на домены

### Принципы границ:

- По бизнес-возможностям (Domain-Driven Design: Bounded Context)
- По требованиям регуляторов (медицина ФЗ-152, финансы ФЗ-115)
- По частоте изменений (стабильные справочники, операционные данные)
- По организационной структуре (соответствие командам-владельцам)

### Решение перекрытий данных:

- Справочный домен - источник истины для: клиентов, услуг, тарифов, врачей
- Master Data Service (MDS) с API чтения + событийная синхронизация изменений
- Медицинские данные: владелец = мед.домен, ИИ получает только анонимные копии
- Финансовые транзакции: владелец = фин.домен, аналитика получает агрегаты
- Контракты данных (Data Contracts) для форматов обмена между доменами
